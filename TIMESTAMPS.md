# Cryptographic timestamps

This repository makes claims whose ORDER matters: a run's axioms and predictions are fixed before the
derivation that tests them. Three independent dates back that up:

1. **The push.** GitHub's repository activity records when each commit arrived (`runs/prereg.py` prints it).
2. **RFC 3161.** A manifest of every tracked file and its SHA-256 — weekly, AND on every push that touches `kala/`,
   `matika/` or `runs/` (2026-10-13; such a run names its manifest by the second) — signed by three independent trust
   authorities (one eIDAS-qualified) and stamped to Bitcoin — `timestamps/`, `./tsa-verify.sh`. Legal standing
   that Bitcoin lacks; Bitcoin has the permanence the authorities lack (see `timestamps/README.md`).
3. **OpenTimestamps.** Frozen files carry a `<name>.ots` proof beside them, committing the file's SHA-256
   to the Bitcoin blockchain — checkable without trusting this repository, GitHub or the authors:
   `ots verify runs/<run>/PREREG.md.ots`.

## What is stamped, and what is not

| Stamped (frozen once written) | Not stamped (living; history is in git) |
|---|---|
| `runs/*/PREREG.md` — stamped AT registration by `prereg.py`, before the agent runs | `runs/PROVE-RUBRIC.md` — amended by rulings; every PREREG cites the commit it was graded by · `kala/` — `AXIOMS.md`, `Axioms.lean`, `Time.lean` change as axioms are verified; each PREREG copies the rows it used verbatim, so the stamped PREREG carries them |
| `matika/*.md`, `patthana/*.md`, `patthana/*.json`, `kathavatthu/*.md`, `kathavatthu/*.json`, `yamaka/*.md`, `yamaka/*.json`, `puggala/*.md`, `puggala/*.json`, `cittuppada/*.md`, `cittuppada/*.json`, `dhatukatha/ALL.md`, `dhatukatha/ALL.json`, `vibhanga/*.md`, `vibhanga/*.json` — GENERATED from the CST (`scripts/matika.py`, `scripts/relata.py`, `scripts/patthana.py`, `scripts/kathavatthu.py`, `scripts/yamaka.py`, `scripts/puggala.py`, `scripts/cittuppada.py`, `scripts/dhatukatha_all.py`, `scripts/vibhanga_pp.py`) and stamped by the weekly job (ruled 2026-11-19, founder: "yes"; until then this table called `matika/` unstamped while the job stamped it). They are regenerated as capture proceeds, so they DO change: the generator itself rotates a changed file's proof to `<name>.rN.ots` and logs it below (`scripts/stamped.py`), and the job stamps the new text. | |
| `runs/*/DERIVATION.md`, `runs/*/RUN.md`, `runs/*/*.lean` | `RESULTS.md` — revised as rungs complete · `runs/INDEX.md` — regenerated on every run (one proof was taken by mistake on 2026-09-30 and is KEPT; the verifier classes the file exempt) |
| `PREREGISTRATION*.md` | `model/` — the working encoding for *The Calculus of Moments*, attempt 1 (`CENSUS.md`, the Lean); its frozen form is Protocol 2's PREREG under `runs/`, stamped there (2026-10-15) · `README.md`, this file |

`ots stamp` overwrites an existing proof, so a stamped file is never edited. A correction is a new file
(for a run: a new run). If a stamped file ever must change, rotate its proof to `<name>.rN.ots` first and
log it here.

**Proofs start PENDING** (calendar attestations) and become Bitcoin-anchored after a few hours;
`./ots-upgrade.sh` (or MA's `/ots`) bakes the Bitcoin attestation in.
